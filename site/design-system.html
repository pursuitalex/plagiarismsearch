Hover / active states pass AA

Interactive fills bind to deeper shades so white text stays legible on press.

  • brand-solid-hover orange/700 · 5.37:1
  • brand-solid-active orange/800 · 8.31:1
  • teal-solid-hover teal/700
  • inverse-hover neutral/800

Brand-locked exception

Default orange/500 and teal/500 fills score 2.81–2.90:1 with white text — below AA. Kept per brief §8 because the hues are the brand's core recognition asset.

Mitigation: never use a 500 fill for the only copy of an instruction; hover/active compensate; body text never sits on a 500 surface.

Checkbox, radio & groups

The native control is replaced with appearance:none, never hidden behind a fake box — so the label, keyboard focus and :checked keep working for free. 18px box, teal-600 fill, 3px focus halo. Never ship a browser-default checkbox.

Chipset · .chipset + .chip-opt

Single choice, compact. Radio semantics with no visible box — use when the options are short and scanned side by side.

Checker form — states

The quick-check form on every checker-first page (build/checker.js). The pages show one state — empty. These are the rest, for the developer who binds the form to the production checker. Every state is the real template with one part swapped, so none of them can drift from the form on the pages.

Check button
Check for plagiarism

Two states only. It is never disabled while idle — pressing it is how a visitor finds out what is missing.

Behaviour

Nothing entered is ever lost
No error, failure or gate clears the text, the files or the switches. A refresh after going offline is the only exception, and the offline alert says so.
Say it next to what it is about
Field problems under the field, file problems in the file’s row, the switches’ problem by the switches. Only failures of the whole check go in an alert, above the button row.
Don’t disable the button
The busy state is the one exception. Everywhere else a press is answered with the reason — a disabled button explains nothing and can’t be focused.
Clear an error when its reason is gone
On the keystroke, the switch, the removed file — the way the AI Detector does it — not on the next submit.
Focus goes where the fix is
After a failed submit, to the first thing to fix. After removing a file, to the next row or the drop zone. The gate takes focus on its first action.
Announce, don’t shout
role="alert" for errors that appear after an action, role="status" for progress and warnings; aria-invalid and aria-describedby tie a field to its note.
The drop zone is a button
Today it is a div a keyboard can’t reach. With role="button" and tabindex, Enter or Space opens the file picker. A file pasted with Ctrl/Cmd+V, or dropped anywhere on the page, is added the same way.
Phones
No drop zone below 768; the Attach file chip opens the picker, and files appear in the same list.
Reduced motion

Open questions

  1. Over 150 words as a guest: does the check run on the first 150, or does the sign-in gate open? The “Over the free limit” note and the gate assume different answers.
  2. The minimum length for a plagiarism check — “Too short” uses 20 words as a placeholder.
  3. Text and files together, or one or the other? The file states assume a file replaces the text field; the product today (Not enough words) reads the file into the field and keeps the row under the drop zone. One of the two should become the rule.
  4. File size: the PDF page says 2 MB for guests and 24 MB signed in, the product’s drop zone says 4 MB per file. Which is current, and does it differ by format?
  5. Error colour. The checker family (live word count, AI Detector notes) uses orange-700 #B84431; the Input component above uses red #DC4444. These states follow the checker. One of the two should give way.
  6. Is there a guest quota beyond the word limit (checks per day)? If so, it needs a state of its own.
  7. After “Starting check…”: does the page move to the report, or does the card wait and show “Report ready”?
  8. Dropbox / OneDrive: pop-up or redirect? A redirect has no “blocked” state, but must bring the visitor back with the form as it was.
  9. All “Draft copy” sentences need review before any of them ship.
